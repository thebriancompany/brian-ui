# Side Navigation

서비스의 페이지를 그룹과 하위 메뉴로 탐색합니다. 현재 페이지는 선택 배경으로
구분하며, 메뉴 이름은 길어도 말줄임하지 않고 줄바꿈합니다.

## 기본 사용

`BrianTheme` 아래에서 유한한 높이를 제공하세요. 기본 너비는 256, 접힌 너비는
64 논리 픽셀입니다. `Row` 안에서는 본문을 `Expanded`로 배치합니다.
사이드바 자체가 너비를 전환하므로 바깥에서 접힘 상태에 따라 고정 너비를
즉시 바꾸지 마세요. 부모가 너비를 고정하면 해당 제약이 우선합니다.

```dart
BrianSideNavigation(
  selectedValue: currentPage,
  onSelected: (value) => setState(() => currentPage = value),
  header: const Text('내 워크스페이스'),
  groups: const [
    BrianSideNavigationGroup(
      label: '워크스페이스',
      items: [
        BrianSideNavigationItem(value: 'home', label: '홈'),
        BrianSideNavigationItem(
          value: 'projects',
          label: '프로젝트',
          children: [
            BrianSideNavigationItem(value: 'active', label: '진행 중'),
            BrianSideNavigationItem(value: 'archive', label: '보관함'),
          ],
        ),
      ],
    ),
  ],
)
```

## 상태와 상호작용

- `selectedValue`와 페이지 이동은 앱에서 관리합니다. 선택 콜백은 활성 페이지
  항목을 실행할 때만 호출되며, 부모 항목은 펼침만 전환합니다.
- 하위 메뉴는 한 단계까지 지원합니다. 모든 `value`는 탐색 영역 안에서 고유해야
  합니다. 전달한 그룹·항목 목록은 변경하지 말고 새 목록으로 교체하세요.
- 초기 선택과 선택 변경 시 해당 하위 항목의 부모를 자동으로 엽니다. 이후에는
  선택 상태를 유지하면서 부모를 직접 접거나 다시 펼칠 수 있습니다. 접으면
  부모에 선택 강조를 표시하고, 다시 펼치면 선택한 하위 항목에 표시합니다.
- `enabled: false`는 클릭·키보드 실행을 막습니다. 부모 비활성화는 자식에도
  적용됩니다. 이미 선택한 항목도 외부 상태로 표시할 수 있습니다.
- `trailing`에 배지나 보조 표시를 넣습니다. 하위 메뉴가 있으면 펼침 표시가
  우선합니다. 아이콘과 보조 표시에 별도의 버튼을 넣지 마세요.

`initialExpandedValues`에 부모 항목의 value를 지정하면 해당 메뉴를 펼친 상태로
시작합니다. 이후에는 사용자 조작으로 전환합니다. 선택이 바뀌면 새로 선택한
하위 항목의 부모를 펼칩니다.

## 글자와 전환 효과

일반 메뉴는 `t4Regular`, 선택 메뉴는 `t4Medium`, 그룹 라벨은 `t2Medium`을
사용합니다. 액션 버튼의 굵은 글자를 그대로 상속하지 않습니다.
접힌 메뉴는 20 논리 픽셀 아이콘을 버튼의 가로·세로 중앙에 배치합니다.

하위 메뉴는 220ms 동안 높이와 투명도를 바꾸고, 같은 시간에 펼침 화살표를
회전합니다. 접히는 즉시 자식의 포인터·포커스·접근성 탐색을 막고 전환이 끝나면
제거합니다. 사이드바 너비와 그룹 라벨도 220ms로 전환하며, 초기 표시는
애니메이션 없이 지정한 상태를 사용합니다. 시스템의 모션 감소 설정
(`MediaQuery.disableAnimations`)이 켜져 있으면 즉시 전환합니다.

## 접기와 보조 팝업

`collapsed`와 `onCollapsedChanged`를 함께 연결하면 접기 버튼이 나타납니다.
콜백으로 받은 값을 다시 전달해야 너비가 바뀝니다. 펼친 상태에서 헤더와 접기
버튼은 같은 줄에 놓입니다. 헤더와 푸터는 접힐 때 숨기며,
`collapsedHeader`와 `collapsedFooter`로 작은 표현을 제공할 수 있습니다.

접힌 메뉴에 호버하면 단독 항목은 이름, 부모 항목은 하위 메뉴 팝업을 보여줍니다.
부모는 클릭·Enter·Space로도 팝업을 열 수 있습니다. 키보드로 열면 첫 활성 자식에
포커스가 이동합니다. Escape 또는 선택 시 트리거로 돌아오고, 바깥 클릭으로 닫을
수 있습니다. 팝업에서 Tab으로 나가면 닫힙니다.
팝업은 `background.layerFloating` 표면과 `shadows.s3` Elevation을 사용하며
테두리는 표시하지 않습니다.

## 아이콘

기본 접기·펼치기 표시는 내부 `CustomPainter`로 그립니다. 공개 아이콘 컬렉션은
제공하지 않습니다. 메뉴의 `icon`은 `Widget`이므로 앱의 `Icon`, SVG 위젯 또는
직접 그린 벡터를 전달할 수 있습니다. `IconTheme`의 크기·색상을 따르게 하세요.
핵심 패키지는 Material·Cupertino나 SVG 패키지에 의존하지 않습니다.

아이콘을 생략하면 접힌 상태에서 라벨의 첫 글자가 표시됩니다. 아이콘만으로
여러 메뉴를 구분해야 하는 화면에는 의미가 명확한 아이콘을 지정하세요.
접힌 상태에도 전체 메뉴 이름이 접근성 라벨로 유지됩니다.

## 표면과 스크롤

`neutral`은 중립 배경으로 영역을 구분하고 `transparent`는 부모 표면을 공유합니다.
투명 배경이 기본 표면과 다르면 `fogColor`를 같은 색으로 지정하세요.
헤더·푸터는 고정하고 메뉴만 스크롤합니다. 스크롤한 내용이 위에 남으면 상단
구분선, 아래에 남으면 32 논리 픽셀 높이의 Scroll Fog를 표시합니다.

## 반응형 구성

화면 전체 너비에 따른 모드 전환은 앱의 `LayoutBuilder`에서 결정합니다.
넓은 화면에는 펼친 메뉴, 중간 너비에는 `collapsed: true`, 좁은 화면에는 메뉴
버튼으로 열리는 별도 탐색 패널을 권장합니다. 모바일에서 패널의 닫기·포커스
복귀·뒤로 가기 정책도 앱이 관리합니다. 문서 사이트에서는 좁은 화면의 메뉴
버튼으로 탐색과 본문을 전환하며 페이지 선택 시 본문으로 돌아갑니다.
사이트는 768 미만에서 메뉴 버튼, 768 이상 1000 미만에서 접힌 메뉴,
1000 이상에서 펼친 메뉴로 시작합니다. 768 이상에서는 직접 접고 펼칠 수 있습니다.

## 접근성 확인

Tab·Shift+Tab으로 탐색하고 Enter·Space로 실행합니다. 선택·비활성·펼침 상태를
semantics로 전달하며 포커스 테두리는 BrianButton을 사용합니다. 메뉴 이름은
짧고 분명하게 작성하고, 라이트·다크·확대 글자·실제 스크린 리더에서 확인하세요.
자동 테스트만으로 모든 접근성 환경의 동작을 보장하지 않습니다.
