# 주석 기준

주석은 코드를 읽는 양을 줄이거나, 코드만으로 놓치기 쉬운 계약을 알려주어야 합니다.
공개 멤버라는 이유로 모두 작성하지 않고, 호출자가 IDE 도움말에서 얻을 정보를
기준으로 판단합니다. 소스를 보면 알 수 있는 값이라도 사용하는 위치에서 바로
확인할 가치가 있으면 남깁니다.

## 남기는 정보

- 상수의 실제 값, 단위, HEX·ARGB 순서, 불투명도.
- 이름만으로 구별하기 어려운 역할의 사용 위치와 전경·배경 조합.
- 입력 제약, null 처리, 예외, 변경 구독과 같은 동작 계약.
- 테마별 차이, 팔레트 교체 시 역할 재계산 여부, 보간 시 밝기 전환 시점.
- 알려진 대비 제한과 다른 API를 선택해야 하는 조건.
- 구현을 바꾸면 깨질 수 있는 이유나 의도. 이는 `//`로 작성합니다.

예를 들어 `blackAlpha400`의 400은 불투명도 40%를 의미하지 않습니다.
실제 값은 사용하는 곳의 IDE 도움말과 API 문서에 노출할 가치가 있습니다.

```dart
/// HEX `#00000021` · ARGB `0x21000000` · 불투명도 12.94%.
static const blackAlpha400 = Color(0x21000000);
```

HEX는 `#RRGGBB` 또는 `#RRGGBBAA`, Dart 정수 색상은 `0xAARRGGBB` 순서입니다.
알파 비율은 `알파 바이트 / 255 × 100`이며, 주석에서는 소수 둘째 자리까지
표시합니다. 반올림한 설명과 정확한 값은 구별하고, 값이 바뀌면 함께 수정합니다.

인스턴스마다 달라질 수 있는 `step400` 같은 속성에 특정 팔레트의 HEX를
고정된 계약처럼 적지 않습니다. 모드별 전체 값은 참조표에서 관리합니다.

## 생략하는 설명

다음은 이름이나 시그니처를 되풀이하므로 추가하지 않습니다.

```dart
/// 모든 값을 명시하여 생성합니다.
const BrianPalette({/* ... */});

/// 주황색 계열입니다.
final BrianColorScale orange;

/// 지정한 값만 교체한 복사본을 반환합니다.
BrianPalette copyWith({/* ... */});
```

생성자, 단순 프로퍼티, 관례적인 `copyWith`, `==`, `hashCode`에 별도 설명이
없어도 괜찮습니다. 반대로 특별한 동작이 있다면 그 차이를 설명해야 합니다.

```dart
/// 팔레트만 교체해도 기존 역할 색상은 재계산하지 않습니다.
///
/// 역할을 다시 연결하려면 [BrianColors.fromPalette]을 사용합니다.
```

## 중복을 줄이는 위치 선택

- 타입 전체에 적용되는 규칙은 타입 설명에 씁니다.
- 각 값마다 다른 정보는 해당 멤버에 씁니다.
- `Pressed`, `Solid`, `Weak` 같은 공통 이름 규칙은 그룹 설명과 가이드에 씁니다.
- 핵심 API의 짧은 예시는 `///`, 여러 API를 묶는 긴 예시는 `doc/`에 씁니다.
- 기존 문장이 부정확하다면 보충 문장을 덧붙이기보다 원래 설명을 수정합니다.

`public_member_api_docs`로 주석 개수를 강제하지 않습니다. `dart doc`의 생성
성공이나 문서화 비율도 주석의 유용성을 대신 평가하지 못합니다.

공식 Effective Dart도 공개 API의 설명을 권장하면서, 이름·시그니처에서 바로
알 수 있는 내용을 반복하지 말라고 안내합니다. 이 저장소는 그 원칙에 따라
실제 사용에 필요한 정보에 집중합니다.

참고: [Effective Dart의 중복 설명 방지 지침](https://dart.dev/effective-dart/documentation#avoid-redundancy-with-the-surrounding-context).
